# 약점 보완 계획

냉정한 평가(2026-11-15)에서 나온 약점 7가지를 어떻게 줄일지 정리한 계획이다. 원칙은 두 가지다.

1. **신뢰가 분량보다 먼저다.** 검수 안 된 내용을 늘리면 위험만 커진다. 새 내용은 검수 체계가 생긴 뒤에 늘린다.
2. **시장 반응을 싸게 먼저 본다.** 스토어 등록과 큰 기능 개발은 지인 베타 결과를 본 뒤에 결정한다.

## 단계

### 0단계 — 지금 시작 (이번 작업)
- 성조 코드 검증기(`tools/check_tones.py`) 만들고 걸린 오류 수정
- 앱 안 "정보" 화면: 버전, AI 음성·검수 상태 고지, 오픈소스 라이선스, 학습 요약
- 베타 안내문과 설문(`docs/BETA.md`)

### 1단계 — 지인 베타 (약 3주)
- 안드로이드 `.apk`를 지인 10~20명에게 직접 설치(스토어 등록 불필요)
- 원어민 검수 의뢰·반영
- 판단 기준(제안): 참가자 절반 이상이 1주 안에 레슨 5개 이상 완주 / 심각한 오류 지적이 단원당 몇 건 이하 / "유료여도 쓰겠다"가 일부라도 나옴
- 통과하면 2단계, 아니면 방향을 다시 정한다(중단 포함).

### 2단계 — 출시 준비와 보강
- 알림, 기록 내보내기, 디자인 개선, 단어 500 이상으로 확대(검수 포함), `.aab` 빌드, 스토어 등록
- 안드로이드 먼저 소규모 공개 → 아이폰

### 3단계 — 차별화
- 말하기 비교 재생, 대화 레슨, 단어 1,000, 수익화 시험(일시불 전체 해제)

## 하지 않는 것 (당분간)
- 광고, 하트 결제, 마이크 발음 채점, 계정·서버(수요 확인 전), 앱 안 통계 수집

## 성공 지표 (베타)
- 설치한 사람 중 첫 레슨을 끝낸 비율, 7일 안에 5레슨 이상 한 비율
- 사용자가 지적한 오류 수(단원별), 소리가 안 나는 기기 수
- "돈을 낸다면 얼마까지" 응답 분포
